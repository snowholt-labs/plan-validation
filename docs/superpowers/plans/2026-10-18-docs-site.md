# Documentation Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the plan-validation documentation as an Astro Starlight site at `https://snowholt-labs.github.io/plan-validation/` with the approved plum design, replacing the GitHub wiki.

**Architecture:** A self-contained Node project in `site/`. Moved wiki pages live in `site/src/content/docs/`; root files GitHub displays (`CHANGELOG.md`, `SECURITY.md`, `CONTRIBUTING.md`, `examples/*.md`) stay the single source and are copied into git-ignored content files by a dependency-free sync script before each build. Starlight component overrides carry the custom shell; a dependency-free checker validates the built site; GitHub Actions builds on pull requests and deploys from `main`.

**Tech Stack:** Node 24 LTS, npm with `package-lock.json`, `astro` 7.4.0, `@astrojs/starlight` 0.42.6 (Pagefind search and Expressive Code copy buttons are built in), Astro's built-in Fonts API with the Fontsource provider, `node:test` for script tests.

**Spec:** [`docs/superpowers/specs/2026-10-18-docs-site-design.md`](../specs/2026-10-18-docs-site-design.md). Visual reference: [`2026-10-18-docs-site-mockup.html`](../specs/2026-10-18-docs-site-mockup.html).

## Global Constraints

- Site URL: `site: 'https://snowholt-labs.github.io'`, `base: '/plan-validation'`.
- Approved direct dependencies: `astro` 7.4.0 and `@astrojs/starlight` 0.42.6, exact pins (no `^`). Anything else, including `starlight-llms-txt` or a link-validator plugin, needs the maintainer's approval with a comparison first. This plan builds `llms.txt`, per-page Markdown and link checking without new packages.
- After every install, run `npm audit --omit=dev` in `site/` and report the result; stop and ask if it shows a high or critical advisory.
- No runtime requests to third parties: no externally hosted fonts, scripts, images or analytics in the built site. Fonts are downloaded at build time and served from the site.
- One editable copy of every page. Synced files are git-ignored and carry a "generated, edit the source" comment.
- The Python tooling stays stdlib-only. The existing `verify` CI job must not need Node.
- Never commit `node_modules/`, `dist/`, `.astro/` or synced content.
- Copy rules: sentence case everywhere, no all-caps labels, no `→` appended to buttons. Footer credit: "Created and maintained by [snowholt](https://github.com/snowholt)." No other personal name.
- Required notices: the README's pilot-release notice on the landing page; "not a benchmark" on the rehearsal sheet and the Examples page; "Independent project, not affiliated with Anthropic, OpenAI or Superpowers." in the footer of every page.
- Quality floor: works at 360px wide with no horizontal scroll, visible keyboard focus, `prefers-reduced-motion` respected, WCAG AA (4.5:1) text contrast in light and dark themes, Starlight's skip link kept.
- Git: phase branches from `plan/docs-site`, PRs into it squash merged after CI and code and security review; final PR into `main` merged with a merge commit. Labels: `documentation`, plus `enhancement` for code phases. Milestone: "Documentation site".
- GitHub settings changes (enable Pages, required check, homepage, wiki) are made only with the maintainer's go-ahead at that step.

## Review Focus

1. A page link written the wiki way (`https://github.com/snowholt-labs/plan-validation/wiki/Usage`) or relative to the repository (`../examples/README.md`) inside a synced or moved page: expected to land on the site page or the GitHub file, never a 404. Pinned by `rewriteLinks` tests in Task 2 and the built-link check in Task 4.
2. Links without the `/plan-validation` base (`/get-started/`): expected to be caught before deploy, since they work on `localhost` but break on GitHub Pages. Pinned by `checkSite` "root-relative link missing base" test in Task 4.
3. Code fences containing link-like text or `/home/` example paths: expected to be left untouched by the link rewriter. Pinned by the fenced-code test in Task 2; the leak check in Task 4 ignores nothing, so Task 3 keeps placeholders such as `<skill-directory>`.
4. A reader in dark mode or with reduced motion: expected readable plum contrast and a static rehearsal sheet. Pinned by the contrast test in Task 6 and the reduced-motion screenshot check in Task 7.
5. A phone at 360px: sidebar, button rows and install tabs must stack with no horizontal scroll. Pinned by the 360px screenshot check in Task 7.
